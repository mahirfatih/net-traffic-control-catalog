# Code of Conduct

## Pledge

Everyone contributing to this repository agrees to the following:

- My contributions will be **accurate**. When I believe something is wrong, I
  will say so plainly.
- My contributions will be **traceable**. A wrong label is worse than no label,
  because a labelled but incorrect entry looks authoritative.
- My contributions will **respect the licence**. NonCommercial or ShareAlike
  data does not enter this repository — the gate refuses it (see
  [`SECURITY.md`](SECURITY.md)).
- I will respect other people's work. Criticism is about the data, never about
  the person.

## Scope

This applies to every interaction here: issues, pull requests, discussions and
commit messages.

This repository holds **data**, not code. Most discussion therefore reduces to
"what category does this host belong to?" — which is not a place for anything
personal.

## Behaviour

Acceptable:

- Saying that a label is wrong, with a reason
- Rejecting a host and writing down **why** it was rejected
- Reverting your own contribution without explanation

Not acceptable:

- Personal attacks, racism, or sexualised harassment
- Filling the space with **hate speech** or **spam**
- Adding data you know to be wrong
- Diminishing somebody else's work

## Enforcement

Violations are permanent: they sit in `git log` and in the issue history. Nobody
is invisible in this repository.

| Stage | Outcome |
| :--- | :--- |
| 1. Private warning | With a reason, to the person who broke the rule |
| 2. Temporary suspension | Reasoned and time-limited |
| 3. Permanent ban | For repeated or severe violations |

## Reporting

Report a violation to **`irtibat@mahirfatih.com`**. If the matter can be public,
an issue is fine — but you are not obliged to put a personal report in public.
Email is equally acceptable.

The name of the person who reported a violation is not shared beyond that
person. Where a violation is acted on, the written record is the investigation
itself and is shared only with the people involved.

## Attribution

These principles follow the approach of [Contributor Covenant](https://www.contributor-covenant.org/)
2.1, but are written for this repository. In a code project the acceptance
criterion is that the code works; in a data catalog what matters is
**correctness** and **traceability** — which is why the first two clauses of the
pledge carry that weight and the rest is Contributor Covenant's.
